# CopySelect metadata clipboard hotfix audit — 2026-09-08

Baseline: CopySelect 3.7.8.16 RC.

## Root cause

`CS_DEFAULTS.includeMetadata` is `false`, but the Metadata page's **Defaults** action explicitly wrote `includeMetadata:true`. That could persist a normal Default-profile installation in metadata-appending mode and produce clipboard payloads such as title/domain/date/text/time/count/URL.

## Fixes

1. Metadata → Defaults now reads the authoritative `CS_DEFAULTS` values, including `includeMetadata:false`.
2. Schema 28 migration repairs the exact Default-profile/standard-metadata configuration generated by the 3.7.8.16 defect. Custom metadata configurations and the Research profile remain enabled.
3. Automatic CopySelect clipboard writes remember the exact formatted payload together with the raw selected text in session storage.
4. Ctrl+Shift+V reads the current clipboard. If it exactly matches CopySelect's remembered formatted payload, it inserts the raw selection. If it does not match, the clipboard text is pasted unchanged. Windows CRLF/LF differences are normalized only for the equality check.

## Stress tests

- Buggy Default-profile metadata state migrates ON → OFF: PASS.
- Custom metadata state remains ON: PASS.
- Research profile metadata remains ON: PASS.
- Metadata Defaults action uses `CS_DEFAULTS.includeMetadata`: PASS.
- Plain-paste equality strips CopySelect envelope: PASS.
- Non-CopySelect clipboard text remains unchanged: PASS.
- CRLF/LF clipboard comparison does not cause false mismatch: PASS.
- JavaScript syntax: PASS.
- Manifest JSON parse: PASS.

This hotfix intentionally does not disable metadata for profiles/configurations that explicitly request it.
